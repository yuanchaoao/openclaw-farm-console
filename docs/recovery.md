# 中断与连接恢复

恢复从现场开始。先读取当前任务记录和已验证的工作流，再并行检查实际下游；旧会话状态、超时、PID、监听端口和 READY 日志仅作线索。避免一边等待旧回执、一边重复安装或轮换健康凭据。

## 固定顺序

| 层 | 真实证据 | 最小修复 |
|---|---|---|
| 本机安装与凭据 | control.py status、SDK 检查、系统凭据库可访问、配置路径 | 修正路径/解锁凭据库；不复制 Token 到配置 |
| Gateway/MCP | 当前实例同一身份的认证 health 与会话列表 | 恢复客户端或核对唯一配对；不生成多套设备身份 |
| 远端文件桥 | 实际配置、回环 capabilities、准确程序哈希与凭据文件权限 | 补缺失资产或重启该实例服务；不重装已健康程序 |
| 远端 → SSH 中继 | 当前隧道公钥指纹、对应 authorized_keys 授权、回环端口能力响应 | 只修该实例公钥/监听范围/反向隧道 |
| 本机 → SSH 中继 | 本地转发实际目标主机、实例独占端口、本机 capabilities | 只修失效转发；端口仍监听也要核对目标 |
| 文件验收 | 唯一测试文件写入、读回内容/哈希、删除后 not_found | 执行已授权范围的完整验收并落盘 |

Gateway 先恢复，再继续依赖它的文件桥安装。远端服务健康时，直接检查中继与本地路径，不能把隧道断开诊断成程序未安装。

## 维护请求未返回

1. 记录原任务 ID、维护 sessionKey、runId、请求编号与目标。
2. 查原会话历史及远端真实文件、程序和服务；同时检查中继能力和本地文件桥。
3. 下游已可用时立即做最终验收，不等待迟到的安装回复。
4. 原任务仍在执行且可能写入时，跟踪它或只进行只读探测；不能启动第二个相同变更。
5. 已确认原执行结束且目标确实未完成时，继续未完成步骤。任务丢失时先核对有副作用的原操作实际结果，再重建失效状态。
6. 请求带唯一编号只提交一次；同一 chat.send 重试复用原 idempotencyKey。不能用新编号掩盖不确定结果。

Console 持久任务显示 blocked 时，应检查 blockerCode、missingEvidence、nextAction 和最近真实健康结果，再从该任务的恢复入口继续。blocked 是缺少具体证据或权限，不等于所有步骤都失败。

## 常见断点

- 凭据文件缺失：仅在能核对所属实例、权限与当前配置时从其受保护备份恢复；绝不跨实例借用凭据。
- 反向隧道连接失败：核对现用 SSH 公钥指纹与中继精确授权行，并检查 PermitListen 的回环地址和独占端口。修改前备份，验证 sshd 配置，再只重连该实例。
- 更换中继后本地端口还监听：验证进程实际转发目的地；只替换确认归属本管理台、该实例独占的旧转发。
- 配对已批准仍报错：区分本机设备配对、远端内部客户端权限、命令执行批准，按身份和完整请求 ID 定位。
- 下载/上传中断：保留本地续传记录与远端上传 ID，重新运行相同路径与内容；先取实际偏移，最终校验 SHA-256。
- 超时与网络错误：检查服务路径，不重复删除、安装、发任务或轮换密钥。401/403 要核对凭据和授权；网络超时不能记录成身份错配。

## 恢复记录

保存首个真实断点、变更前后哈希/公钥指纹、授权备份路径、最小变更、最终各层能力、文件验收及尚缺证据。下一次恢复复用本次已验证步骤，但仍逐实例核对身份和现场；公开问题报告只保留脱敏摘要。健康的其他实例、VPN、代理与共享转发服务不得因单实例故障被整体重启。
